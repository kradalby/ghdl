# ghdl

Scrape cumulative download/pull counts for a project's release artifacts and
container images, record them over time in SQLite, and serve that history as
JSON for Grafana. GitHub, Docker Hub, and GHCR all show a live count but keep no
history — ghdl gives you the graph.

Primary target: [`juanfont/headscale`](https://github.com/juanfont/headscale),
but every source is a configurable list.

## What it collects

| Source | What | Granularity |
| --- | --- | --- |
| GitHub release assets | `download_count` per asset | per release × asset, with `os`/`arch`/`format` parsed from the filename |
| Docker Hub | `pull_count` | repo-wide total (Docker Hub exposes no per-tag pulls) |
| GHCR | container pulls | repo-wide total **and** per-version |

Counts are cumulative and stored **on change** — a snapshot row is written only
when a count actually moves, so frozen old releases stop producing rows.

## GHCR has no download API

GitHub exposes no official download-count API for GHCR containers
([github/community#146215](https://github.com/orgs/community/discussions/146215)),
so ghdl scrapes the package web UI. The parsers are backed by saved-HTML fixture
tests (`collect/testdata/`): if GitHub changes the markup, the tests fail loudly
rather than the collector silently recording nothing. **When an official API
ships, replace the scrape** — see the `TODO(ghcr)` in `collect/ghcr.go`.

## Running

```
ghdl --state-dir=/var/lib/ghdl
```

It joins the tailnet as its own node (`--hostname`, default `ghdl`) and also
serves a local listener (`--local-addr`). The JSON API and `/metrics` are
reachable at `http://ghdl/` from anywhere on the tailnet.

Configuration is via flags or `GHDL_`-prefixed env vars. Secrets come only from
the environment: `GHDL_GITHUB_TOKEN` (raises the API rate limit) and `TS_AUTHKEY`
(unattended tailnet enrolment). `--dev` serves local HTTP only, without joining
the tailnet.

### Endpoints

- `GET /api/series?source=&repo=` — list tracked series (Grafana variables).
- `GET /api/timeseries?source=&repo=&by=os|arch|format|release|asset|none&from=&to=`
  — aggregated step-function download counts. `from`/`to` are unix seconds
  (Grafana millisecond epochs are tolerated).
- `GET /metrics` — scrape-health only (`ghdl_last_success_timestamp`,
  `ghdl_scrape_errors_total`, `ghdl_github_rate_limit_remaining`,
  `ghdl_series_total`). The download history lives in SQLite, not Prometheus.

## Storage & backup

A single SQLite file (`<state-dir>/ghdl.db`), opened with WAL — designed to be
replicated with [litestream](https://litestream.io). Schema migrations run
through [squibble](https://github.com/tailscale/squibble) against
`db/schema.sql`; queries are generated by [sqlc](https://sqlc.dev)
(`sqlc generate`).

## Grafana

Two dashboards are generated from Go with the Grafana Foundation SDK
(`nix build .#grafanaDashboards`, or `go run ./cmd/dashboard -out DIR`):

- `ghdl.json` — the data, over the Infinity datasource pointed at `/api`.
- `ghdl-service.json` — scrape health, over Prometheus.

## Development

Everything routes through the flake:

```
nix flake check      # build, race tests, lint, format, module eval
nix build .#grafanaDashboards
nix run .#default -- --dev --state-dir=/tmp/ghdl
go run ./cmd/vendorhash check   # keep flakehashes.json in sync (prek runs this)
```
